# CnizOS — Риски, зависимости и план первой рабочей версии

## 1. Окружение (факт на 2026-10-12)

- Workspace пустой — проекта Зоро нет, считаем его внешним.
- Python 3.13.16 ✓, Node 20.20.2 ✓
- PostgreSQL / Docker отсутствуют в песочнице — для локальной разработки будет Docker Compose, в песочнице — SQLite-заглушка для тестов или внешний Postgres.
- Всё бесплатное: OSS стек, без платных SaaS.

## 2. Риски и митигация

| # | Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|---|
| R1 | Исходный код Зоро неизвестен | Высокая | Среднее | Интеграция через отдельный `cnizos_client.py`, не трогая ядро. После получения кода — адаптация за 1-2 дня. |
| R2 | Нет Windows для теста Bridge | Высокая в песочнице | Высокое | Bridge имеет `mock` режим (`--mock`) — эмулирует `app.launch` без реального exec. Реальные тесты — на машине владельца. |
| R3 | PWA Push не работает в iOS | Средняя | Низкое | Fallback: in-app уведомления + polling. Не блокирует MVP. |
| R4 | Конфликт редактирования | Средняя | Среднее | ETag + 409, без CRDT в v1. |
| R5 | Потеря WSS | Средняя | Среднее | Reconnect backoff, команды в БД `queued` → `expired`. |
| R6 | Разрастание схемы БД | Низкая | Среднее | Alembic миграции, мягкое удаление. |

## 3. Зависимости

- **Критично для Этапа 2:** PostgreSQL 16, Python FastAPI, Node Vite.
- **Для Bridge:** Windows 10/11, Python на целевой машине, права на запуск приложений.
- **Для Zoro:** сеть между Зоро и Backend (локальная или через HTTPS).

## 4. План первой рабочей версии (MVP) — Этапы 2-3

### Этап 2: Основа (1-2 недели) — *следующий шаг после утверждения архитектуры*

**Цель:** запускаемое приложение с настоящей авторизацией и пустыми модулями.

- [ ] Монорепозиторий `cnizos/` по структуре ТЗ §19
- [ ] `backend/` — FastAPI skeleton, `/health`, Alembic, подключение к Postgres (Docker Compose), `users`+`sessions`
- [ ] Auth: `POST /auth/setup` (один владелец), login, JWT, refresh, middleware
- [ ] `frontend/` — Vite + React + Tailwind + shadcn, тёмная тема (графитовый #0A0A0B + #4ADE80), React Router, TanStack Query
- [ ] Навигация: Sidebar (desktop) + BottomNav (mobile), 9 разделов-заглушек, header с реальными статусами (`/health` + `/bridge/status`)
- [ ] Глобальный поиск-заглушка, командная палитра (Cmd+K)
- [ ] Docker Compose: `backend` + `postgres` + `pgadmin` (опц.)
- [ ] Тесты: auth flow, health

**Критерий готовности Этапа 2:** `docker compose up` → открыть `http://localhost:5173` → пройти setup → видеть пустой Dashboard с реальным статусом «Bridge offline».

### Этап 3: Основные данные (2-3 недели)

**Цель:** системой можно пользоваться без Windows.

- [ ] Миграции для `projects`, `tasks`, `notes`, `tags`
- [ ] CRUD Projects (включая страницу проекта, статусы, дедлайны, `local_path`)
- [ ] Planner: tasks с `due_date`, `recurrence`, напоминания (APScheduler), представления (список/сегодня/просрочено/календарь)
- [ ] Memory: Markdown, теги, коллекции, FTS (`body_tsv`), связи `project_notes`
- [ ] Dashboard: виджеты от реальных агрегатов (`/dashboard/summary`), быстрые создания
- [ ] Поиск: `/search` по всем типам
- [ ] Activity logs
- [ ] Тесты: создание задачи, поиск заметки, связь проекта

**Критерий:** создать 2 проекта, 5 задач, 3 заметки → всё видно в Dashboard и находится поиском.

### Этап 4: Синхронизация и PWA (1 неделя)
- PWA manifest + service worker, адаптивность, хранение сессий, `devices` таблица, резервное копирование.

### Этап 5: Bridge (1-2 недели)
- Python Bridge, WSS, allow-list, 7 действий, heartbeat, идемпотентность.

### Этап 6: Zoro (1 неделя)
- `cnizos_client.py`, интент-хэндлеры, Zoro Hub в веб.

### Этап 7-8: Automation, Creative, тесты, деплой.
